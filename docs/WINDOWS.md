# Запуск под Windows

Два способа, оба на Windows 10/11 (64-бит):

* **Без Docker (рекомендуется)** — Python + скрипты `windows\*.cmd`. Проще, меньше ресурсов, монитор открывается в браузере.
* **Docker Desktop** — те же контейнеры, что на Linux-сервере (`windows\docker.cmd`).

Все скрипты можно запускать двойным щелчком в Проводнике или из терминала в папке репозитория.
Настройки — в файле `.env` в корне репозитория (создаётся из `.env.example` при первом запуске).

## 1. Установка без Docker

1. Установите **Python 3.12** (64-бит) и **Git**. Проще всего из терминала (PowerShell):

   ```powershell
   winget install -e --id Python.Python.3.12
   winget install -e --id Git.Git
   ```

   Или с сайтов python.org и git-scm.com. При установке Python отметьте «Add python.exe to PATH».
   Подойдут Python 3.11–3.14, скрипт сам найдёт подходящий через `py` (предпочитает 3.12). Выбрать версию явно:
   `set HOPE_PYTHON=py -3.13` перед запуском `install.cmd` (или путь к `python.exe` без пробелов).

2. Скачайте репозиторий и выберите ветку стратегии:

   ```powershell
   cd $HOME\Documents
   git clone https://github.com/iamful-code/hope
   cd hope
   git checkout strategy/queue-mm          # или strategy/ft-e0v1en, strategy/ft-binhv45
   ```

3. Запустите **`windows\install.cmd`**. Он создаст `.venv`, поставит зависимости (первый раз несколько минут)
   и файл `.env`. На ветках `strategy/ft-*` он сам добавит Freqtrade (там в `.env.example` стоит `HOPE_EXTRAS=freqtrade`).
   После `git pull` или смены ветки **обязательно** запускайте `install.cmd` ещё раз: пакет ставится обычной
   установкой (не `pip install -e`), чтобы работать из папок с кириллицей вроде `C:\Users\Администратор`,
   поэтому изменения кода подхватываются только переустановкой (это быстро, зависимости не качаются заново).

## 2. Запуск

**`windows\start.cmd`** — всё сразу:

* в отдельном свёрнутом окне «hope monitor» стартует монитор, через пару секунд открывается браузер
  `http://127.0.0.1:8000/`;
* в текущем окне работает движок paper-торговли по стратегии из `STRATEGY_CONFIG` в `.env`;
* при сбое (обрыв сети, ошибка стратегии) движок сам перезапускается через 15–120 с;
* остановка — `Ctrl+C` в окне движка (на вопрос «Завершить выполнение пакетного файла» ответьте `Y`),
  затем закройте окно монитора. Результаты остаются в `data\hope.db`.

Отдельные скрипты:

| Скрипт | Что делает |
|---|---|
| `windows\run.cmd` | только движок (с автоперезапуском) |
| `windows\monitor.cmd` | только монитор; `--db data\hope.db,data\bt.db` — несколько БД, `--port 8001` |
| `windows\backtest.cmd` | бэктест по архиву сделок Bybit, например `--from 2026-09-17 --to 2026-09-25 --mode candles --db data\bt.db` |
| `windows\autostart.cmd on` | запуск движка и монитора (свёрнуто, без браузера) после входа в Windows; `off` — выключить |
| `windows\docker.cmd` | то же в Docker Desktop, см. раздел 4 |

Все параметры команд `hope` передаются как есть, например другая стратегия и ограничение по времени:

```bat
windows\run.cmd -c strategies\example_ema\config.yaml --duration 3600
windows\run.cmd --set strategy.params.min_spread_bps=8
```

Можно и без скриптов, из терминала: `.venv\Scripts\hope.exe run`, `.venv\Scripts\hope.exe monitor --open`
(команда `hope` сама читает `.env` из текущей папки).

## 3. Долгий тест на домашнем ПК

* Отключите сон: «Параметры → Система → Питание → Переводить в спящий режим: Никогда»
  (или `powercfg /change standby-timeout-ac 0` в терминале администратора).
* `windows\autostart.cmd on` — после перезагрузки или входа в Windows всё поднимется само.
* Монитор по умолчанию доступен только с этого компьютера (`MONITOR_HOST=127.0.0.1`), поэтому брандмауэр
  Windows ничего не спрашивает. Чтобы смотреть с телефона в домашней сети, поставьте в `.env`
  `MONITOR_HOST=0.0.0.0` и разрешите доступ в окне брандмауэра; адрес — `http://<IP компьютера>:8000/`.
* Закрытие окна движка крестиком тоже корректно завершает запуск (итоги пишутся в БД), но надёжнее `Ctrl+C`.

## 4. Docker Desktop

1. Установите Docker Desktop (нужен WSL 2, установщик предложит сам) и дождитесь «Engine running».
2. `windows\docker.cmd` (то же, что `windows\docker.cmd up`) — сборка образа и запуск движка и монитора,
   браузер откроется сам. Стратегия — `STRATEGY_CONFIG` в `.env`, для веток `strategy/ft-*` образ собирается с Freqtrade.
3. `windows\docker.cmd logs` — лог движка, `down` — остановить, `ps` — состояние.

Данные в Docker на Windows хранятся в томе `hope-data`, а не в папке `data`: SQLite в режиме WAL ненадёжно работает
на папках Windows, проброшенных в контейнер. Скопировать БД для анализа: `windows\docker.cmd export-db`
(появится `data\hope-docker.db`, открыть — `windows\monitor.cmd --db data\hope-docker.db`).

## 5. Если что-то не так

| Симптом | Что сделать |
|---|---|
| `Python 3.11 or newer was not found` | установите Python (шаг 1) и откройте новое окно терминала |
| `hope is not installed yet` | запустите `windows\install.cmd` |
| `ModuleNotFoundError: No module named 'hope'` в конце установки | старая версия `install.cmd` ставила пакет через `pip install -e`, а это не работает в папке с кириллицей в пути. Выполните `git pull` и запустите `windows\install.cmd` ещё раз |
| В логе `REST instruments недоступен ... 403` | Bybit не отвечает по REST из вашей страны/сети. Движок продолжает работу на публичном WebSocket, шаги цены выводит из потока — это нормально |
| В логе `disconnected ... reconnect` | обрыв связи, движок переподключается сам |
| Монитор пишет «БД не найдена» / нет запусков | движок ещё не стартовал или пишет в другую БД; проверьте `MONITOR_DB` в `.env` |
| Порт 8000 занят | `MONITOR_PORT=8001` в `.env` |
| Кракозябры в логе, сохранённом в файл | скрипты включают UTF-8 (`PYTHONUTF8=1`), откройте файл как UTF-8 |
| Антивирус ругается на `hope.exe` в `.venv\Scripts` | это стандартный лаунчер pip для консольной команды, добавьте папку репозитория в исключения |
